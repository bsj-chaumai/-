QD Framework

Output đánh giá cho QD — từng giai đoạn

QD và Reviewer tách rời. Tài liệu này chỉ dành cho QD: check có link / đúng người approve / 指摘 trong ngưỡng → ĐỦ hoặc CHƯA ĐỦ.

Cách QD đánh giá

Mở checklist giai đoạn ├─ Thiếu mục / High>0 → CHƯA ĐỦ → trả 担当 └─ Đủ hết → ĐỦ → cho sang bước sau

Checklist QD từng giai đoạn

1 · CHƯA ĐỦ → Dir/PM

要件定義・PJ計画書

#Output QD cần thấyĐỦ khi
1要件定義書Có link
2PJ計画書Có link; có milestone + ngày
3Ticket / WBSCó trên Backlog
4Approve kháchNgày + tên + link
5Critical/High còn mở= 0
2 · CHƯA ĐỦ → BrSE/Dir

設計（SPEC / 設計書）

#Output QD cần thấyĐỦ khi
1SPECCó link
2ACCó link
3Bảng nhánh / trạng tháiCó link hoặc mục trong SPEC
4Review Dev và QCApprove/comment của cả hai
5Version / ngày khóaCó ghi
6Critical/High còn mở= 0
3 · CHƯA ĐỦ → Designer

デザイン

#Output QD cần thấyĐỦ khi
1Figma Final/ApprovedCó link + dấu Final/Approved
2State Error và EmptyCó frame — hoặc N/A + lý do
3Handoff ↔ SPECCó mapping
4Approve Dir và DevCả hai đã xác nhận
5Critical/High còn mở= 0
4 · CHƯA ĐỦ → Dev · ĐỦ = Ready for QA

開発

#Output QD cần thấyĐỦ khi
1PR gắn ticketPR ghi rõ ticket
2Code review approve≥ 1 approve từ người khác
3影響範囲メモCó ghi (kể cả “không có”)
4Build env testCó version/commit
5Critical/High còn mở= 0
5 · CHƯA ĐỦ → QC / Dev

検証

#Output QD cần thấyĐỦ khi
1テスト計画Có link
2テスト仕様書Có link
3Kết quả chạy test% + Pass/Fail + version
4Bug ticketsĐếm được theo severity
5品質サマリーGo hoặc No-Go
6% case In-scope đã chạy= 100%
7Critical/High còn mở= 0 (hoặc waiver)
6 · Thiếu Go/手順/Rollback → không deploy

リリース

#Output QD cần thấyĐỦ khi
1Go / No-GoNgười duyệt + thời điểm + version
2リリース手順書Có link
3Rollback計画Có link
4Smoke productionPass
5Báo cáo hoàn tấtGiờ xong + version + đã gửi
6Critical/High sau release= 0 (hoặc ETA thống nhất)

3 câu cho QD:
1) Chỉ check có link / đúng người approve / 指摘 trong ngưỡng.
2) CHƯA ĐỦ → trả 担当; không review nội dung thay Reviewer.
3) ĐỦ → cho giai đoạn đi tiếp.
