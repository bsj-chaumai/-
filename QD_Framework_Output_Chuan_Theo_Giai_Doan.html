QD Framework

Output đánh giá chuẩn theo giai đoạn (2 vòng)

Vòng 1 kiểm tra đủ điều kiện. Chưa đủ thì trả 担当 đối ứng. Chỉ khi đủ mới sang Vòng 2 để xếp mức A/B/C/D. Cách tính điểm chi tiết hiện 未確定.

Bức tranh tổng quát

Giai đoạn (要件 → 設計 → デザイン → 開発 → 検証 → リリース) │ ▼ VÒNG 1: Đủ điều kiện chưa? (mục bắt buộc + số 指摘) │ ┌────┴────┐ ▼ ▼ CHƯA ĐỦ ĐỦ │ │ ▼ ▼ Liên hệ VÒNG 2: Chấm điểm sâu → A/B/C/D 担当 đối ứng rồi đánh giá lại Vòng 1
VòngCâu hỏiKết quả
Vòng 1Đã đủ điều kiện để review chưa?ĐỦ / CHƯA ĐỦ
Vòng 2Nội dung đạt mức nào?A / B / C / D (công thức điểm 未確定)
Vòng 2 chỉ làm khi Vòng 1 = ĐỦ. Thiếu mục bắt buộc hoặc 指摘 vượt ngưỡng → không chấm điểm.

Vòng 1 — Ngưỡng 指摘

Mức 指摘Ngưỡng còn mở
Critical / Blocker0
High0
Medium / LowCho phép tạm nếu có owner + hạn xử lý

Vòng 2 — Mức A–D (định nghĩa tạm)

MứcÝ nghĩa
AĐủ, rõ, ít phải hỏi lại
BDùng được; còn vài điểm nhỏ
CDùng được có điều kiện; còn thiếu chỗ quan trọng
DYếu; dễ hiểu nhầm, rủi ro cao
Công thức / trọng số tính điểm: 未確定. Hiện chỉ xếp mức theo trục đánh giá của từng giai đoạn.

Output chuẩn từng giai đoạn

Giai đoạn 1

要件定義・PJ計画書

担当Dir / PM
Mục tiêuChốt làm gì, không làm gì, khi nào xong

Vòng 1 — Mục bắt buộc

#MụcOK khi
1要件定義書In/Out, mục tiêu, actor
2PJ計画書Milestone + ngày + owner
3Ticket / WBSTách việc + estimate sơ bộ
4Approve kháchNgày + tên + link
ĐỦ đủ 4 mục + Critical/High = 0
CHƯA ĐỦ → liên hệ Dir/PM đối ứng

Vòng 2 — Trục chấm (công thức 未確定): Phạm vi rõ · Kế hoạch khả thi · Sẵn sàng triển khai · Đồng thuận khách

Giai đoạn 2

設計（画面仕様書 SPEC / 設計書）

担当BrSE / Dir
Mục tiêuĐủ để Dev code và QC test
#MụcOK khi
1SPECField, validation, lỗi, quyền, flow
2ACChecklist / Given–When–Then
3Bảng nhánhNhánh chính đã ghi
4Review Dev + QCCritical/High = 0
ĐỦ đủ 4 mục + Critical/High = 0
CHƯA ĐỦ → liên hệ BrSE/Dir

Vòng 2 — Trục chấm: Đủ để code · Đủ để test · Bao phủ nhánh · Khóa version

Giai đoạn 3

デザイン

担当Designer
Mục tiêuFigma đúng SPEC, đủ state
#MụcOK khi
1Figma FinalĐủ màn, Final/Approved
2StateBình thường + Error + Empty
3HandoffFrame ↔ SPEC; copy chính thức
4Approve Dir + DevĐúng nghiệp vụ; làm được
ĐỦ đủ 4 mục + Critical/High = 0
CHƯA ĐỦ → liên hệ Designer

Vòng 2 — Trục chấm: Khớp SPEC · Đủ state · Handoff · Nhất quán

Giai đoạn 4

開発

担当Dev Lead / Dev chính
Mục tiêuCode đúng; bàn giao test được
#MụcOK khi
1PR gắn ticketRõ ticket
2Review approve≥1 approve; High = 0
3影響範囲メモGhi vùng ảnh hưởng
4Build testVersion/commit; QC biết chỗ test
ĐỦ = Ready for QA
CHƯA ĐỦ → liên hệ Dev

Vòng 2 — Trục chấm: Đúng scope · Review · Ảnh hưởng · Sẵn sàng test

Giai đoạn 5

検証

担当QC
Mục tiêuCó số liệu cho Go / No-Go
#MụcOK khi
1テスト計画Phạm vi, lịch, môi trường, tiêu chí Pass
2テスト仕様書Map AC + regression
3Kết quả test% chạy, Pass/Fail, version
4Bug ticketsSeverity + tái hiện
5品質サマリーGo / No-Go có số liệu
ĐỦ đủ 5 mục + Critical/High = 0
CHƯA ĐỦ → liên hệ QC / Dev

Vòng 2 — Trục chấm: Bao phủ · Thực thi · Bug mở · Kết luận

Giai đoạn 6

リリース

担当Dir / Release owner
Mục tiêuLên prod an toàn, có rollback
#MụcOK khi
1Go / No-GoNgười duyệt + thời điểm + version
2リリース手順書Từng bước + ai làm
3Rollback計画Khi nào / cách rollback
4Smoke productionPass
5Báo cáo hoàn tấtGiờ xong + version + đã gửi
ĐỦ đủ 5 mục; không deploy nếu thiếu Go/手順/Rollback
CHƯA ĐỦ → liên hệ Dir

Vòng 2 — Trục chấm: Chuẩn bị · Thực thi · Xác nhận sau · Đóng vòng

3 câu nhớ nhanh:
1) Vòng 1: đủ mục bắt buộc chưa? 指摘 có vượt chưa?
2) Chưa đủ → gọi 担当 đối ứng — không chấm điểm.
3) Đủ rồi → Vòng 2 xếp A/B/C/D (công thức điểm 未確定).
