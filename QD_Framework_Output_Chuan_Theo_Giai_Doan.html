QD Framework

Đánh giá giai đoạn theo bảng quy chuẩn

QD không bắt buộc là người review nội dung. QD đối chiếu bảng quy chuẩn bằng bằng chứng (link, approve, số 指摘) để kết luận đủ chuẩn hay cần 担当 đối ứng.

Tách vai trò

Vai tròAiLàm gì
Làm / review nội dung担当 giai đoạnTạo output, review chuyên môn, sửa 指摘
Đánh giá theo chuẩnQDSo bảng quy chuẩn → ĐỦ/CHƯA ĐỦ → xếp A–D → yêu cầu đối ứng
担当 tạo output (+ review nội dung nếu có) │ ▼ QD đối chiếu BẢNG QUY CHUẨN (không cần là reviewer chính) │ ├─ Vòng 1: Đủ chuẩn? → ĐỦ / CHƯA ĐỦ │ CHƯA ĐỦ → trả 担当 đối ứng └─ Vòng 2: (khi ĐỦ) xếp A/B/C/D theo bằng chứng

QD kiểm bằng gì? (không cần review sâu)

Câu hỏiCách kiểm
Output bắt buộc có chưa?Có link file/ticket/Figma/PR/Sheet?
Đúng người đã xác nhận chưa?Có approve / ký của đúng vai trò?
指摘 vượt ngưỡng chưa?Critical/High còn mở = 0
Cho sang bước sau?Vòng 1 = ĐỦ thì cho; CHƯA ĐỦ thì dừng
Review sâu nội dung = việc của 担当 / reviewer được chỉ định. QD chỉ spot-check khi bằng chứng yếu hoặc rủi ro cao.

Ngưỡng Vòng 1

Mức 指摘Còn mở tối đa
Critical / Blocker0
High0
Medium / LowCó owner + hạn xử lý
Công thức điểm Vòng 2: 未確定. Hiện xếp A–D theo trục + bằng chứng.

QD check gì từng giai đoạn

1 · 担当: Dir/PM

要件定義・PJ計画書

Vòng 1: 要件定義書 · PJ計画書 · Ticket/WBS · Approve khách (đủ link)

ĐỦ → xếp mức Vòng 2
CHƯA ĐỦ → liên hệ Dir/PM

Vòng 2: Phạm vi · Kế hoạch · Sẵn sàng · Đồng thuận

2 · 担当: BrSE/Dir · Reviewer gợi ý: Dev+QC

設計 SPEC

Vòng 1: SPEC · AC · Bảng nhánh · Record review Dev+QC

ĐỦ → Vòng 2
CHƯA ĐỦ → liên hệ BrSE/Dir

Vòng 2: Đủ code · Đủ test · Nhánh · Khóa bản

3 · 担当: Designer · Reviewer gợi ý: Dir+Dev

デザイン

Vòng 1: Figma Final · Error/Empty · Handoff · Approve Dir+Dev

ĐỦ → Vòng 2
CHƯA ĐỦ → liên hệ Designer

Vòng 2: Khớp SPEC · State · Handoff · Nhất quán

4 · 担当: Dev · Reviewer: Dev khác (PR) — QD không thay code review

開発

Vòng 1: PR gắn ticket · Approve · 影響範囲 · Build test

ĐỦ = Ready for QA
CHƯA ĐỦ → liên hệ Dev

Vòng 2: Scope · Review · Ảnh hưởng · Sẵn sàng test

5 · 担当: QC · QD audit số liệu

検証

Vòng 1: テスト計画 · 仕様書 · Kết quả · Bug · 品質サマリー Go/No-Go

ĐỦ + Critical/High = 0
CHƯA ĐỦ → liên hệ QC/Dev

Vòng 2: Bao phủ · Thực thi · Bug · Kết luận

6 · 担当: Dir · QD audit giấy tờ trước/sau deploy

リリース

Vòng 1: Go · 手順 · Rollback · Smoke · Báo cáo

ĐỦ mới đóng release
Thiếu Go/手順/Rollback → không deploy

Vòng 2: Chuẩn bị · Thực thi · Xác nhận · Đóng vòng

3 câu cho QD:
1) Không cần là reviewer chính — đối chiếu bảng quy chuẩn + link + số 指摘.
2) CHƯA ĐỦ → gọi 担当 đối ứng; chưa ĐỦ thì không chấm điểm.
3) ĐỦ → xếp A/B/C/D; chỉ spot-check khi bằng chứng yếu / rủi ro cao.
